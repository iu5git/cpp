# Первая часть — указатели

# 1. Составные типы данных

**Составные типы данных**

C++ поддерживает набор типов данных, которые определяются на основе других существующих (базовых)типов данных. Они называются **составные типы** (композитные типами) данных и обладают дополнительными свойствами и поведением для решения задач.

В C++ поддерживаются следующие *составные типы*:

- Функции
- Массивы в стиле C
- Типы указателей (**Pointer**):
  - Указатель на объект
  - **Указатель** на функцию
- Указатель на типы элементов:
  - **Указатель** на элемент данных
  - Указатель на функцию-член
- Типы ссылок:
  - Ссылки на значения L (**lvalue references**)
  - Ссылки на значения R (rvalue references)
- Перечисляемые типы (**Enum**erated types):
  - Перечисления без области видимости (Unscoped enumerations)
  - Ограниченные перечисления (Scoped enumerations)
- Типы классов:
  - Структуры (**Structs**)
  - Классы (Classes)
  - Объединения (Unions)

**Составной тип: функции.**

```cpp
void doSomething(int x, double y){
}
```

Тип этой функции — `void(int, double)`. Этот тип состоит из основных типов, что делает его составным типом. Конечно, функции также обладают своими особыми свойствами (например, возможностью вызова).

В этой лекции рассмотрим некоторые из наиболее простых составных типов, включая, `pointers` и `lvalue references` , а на следующей `unscoped enumerations`, `scoped enumerations`, и первый тип класса: `structs`.

# 2. Указатель на объект

```cpp
#include <iostream>

int division(int val, int divider) {
    int integer{val/divider};
    int remainder(val%divider);
}

int main() {
    int value{42};
    int divider(5);
    std::cout << value << '\n';

    division(value, divider );
    std::cout << value  << '\n';

    return 0;
}
```

Программа ставит задачу - как вернуть из функции два и более значений (не используя глобальные переменные)

<!--Или необходимо передать в функцию очень большой объект (при передаче параметров происходит копирование).-->

В программировании на C++ передача данных — это управление ресурсами. `Указатели` и `ссылки` решают три ключевые задачи:

• **Эффективность:** Позволяет избежать дорогостоящего копирования больших объектов (тяжелых структур, векторов, строк). Вместо копирования мегабайта данных передается лишь небольшой адрес в памяти.

• **Изменение данных (In-Out параметры):** Позволяют функции модифицировать оригинальный объект, находящийся вне её области видимости, а не его локальную копию.

• **Разделение ресурсов (Shared State):** Разные части программы могут иметь доступ к одному и тому же экземпляру объекта в памяти.

## Объект и память

Каждая переменная в C++ — это объект, занимающий определенный непрерывный участок физической памяти (оперативной памяти).

• Объект характеризуется типом (определяет размер в байтах и правила интерпретации бит) и значением.

• Память можно представить как гигантский массив ячеек, где у каждого байта есть свой уникальный порядковый номер.

```cpp
char ch {'Y'};
std::cout << ch << '\n';  // вывод на экран значения переменной ch
std::cout << &ch << '\n'; // вывод на экран адреса переменной ch
```

```text
Y
0x002A07FE
```

`Адрес объекта` — это адрес первого байта области памяти, занимаемой объектом.

• При выводе адрес часто отображается в шестнадцатеричном формате.

## Получение адреса

Для получения адреса объекта используется оператор:

`&`

Конкретный адрес заранее неизвестен и может меняться между запусками.

### Что такое указатель

объект, который хранит адрес объекта соответствующего типа. Указатель также может иметь нулевое значение — `nullptr`, означающее, что он не указывает на объект.

Например:

```cpp
int value{42};

int* ptr;
ptr = &value;
```

Теперь:

```text
       значение          имя          тип
    ┌───────────┐
    │    42     │       value        int
┌─▶ ├───────────┤
│   │           │
│   ├───────────┤
│   │           │
│   ├───────────┤
│.      ...
│
│
│   ├───────────┤
└─  │0x0027FEA0 │         ptr         int*
    └───────────┘
```

Сам `Указатель` это тоже объект, для него также выделяется память.

в памяти с именем `ptr` хранится адрес переменной `value`.

**Что означает `int*`**

```cpp
int* ptr;
```

Можно читать:

> `ptr` — указатель на `int`.

А:

```cpp
double* ptr;
```

означает:

> `ptr` — указатель на `double`.

Тип указателя определяет тип объекта, к которому можно обратиться через этот указатель.

## Разыменование указателя

```cpp
    int value{42};
    int* ptr{&value};

    std::cout << *ptr; //42
```

`*ptr` для получения доступа к значению, хранящемуся по этому адресу используют *Оператор разыменования* `*` (иногда также называемый *оператором косвенного доступа* ), который возвращает значение по адресу памяти в виде `lvalue`:

>В простом случае операторы `&` и `*` позволяют выполнить противоположные по смыслу действия: получить адрес объекта и обратиться к объекту через этот адрес.

### Изменение объекта через указатель

```cpp

    int* ptr{&value};

    *ptr = 100;
```

Теперь:

```cpp
    std::cout << value;
```

Получим:

```text
100
```

## Нулевые указатели `nullptr`

Указатель может иметь нулевое значение, обозначающее, что он не указывает на объект. В современном C++ для инициализации такого указателя обычно используют `nullptr`.

Самый простой способ создать нулевой указатель — использовать инициализацию значения:

```cpp
int* ptr{nullptr};
```

**Проверка указателя**

Можно написать:

```cpp
if (ptr != nullptr)
{
    std::cout << *ptr;
}
```

Или:

```cpp
if (ptr)
{
    std::cout << *ptr;
}
```

Оба варианта проверяют, является ли **указатель ненулевым**. Такая проверка необходима перед разыменованием, но сама по себе не гарантирует, что указатель действителен и указывает на существующий объект.

**Разыменование нулевого указателя приводит к неопределённому поведению (undefined behavior UB).**

Вот так нельзя:

```cpp
int* ptr{nullptr};
...

std::cout << *ptr;
```

Нулевой указатель не указывает на объект, поэтому разыменовывать его **нельзя**. Такое действие приводит к **неопределённому поведению**.

**Неопределенное поведение (undefined behavior UB)**

Если программа делает то, для чего стандарт C++ не определяет корректного результата, возникает **undefined behavior**.

Программа может:

- аварийно завершиться;
- вывести что-то странное;
- «работать»;
- сломаться позже.

Стандарт C++ не гарантирует никакого конкретного результата при неопределённом поведении.

Именно поэтому нельзя разыменовывать недействительный указатель.

Устаревшие литералы нулевых указателей: `0` и `NULL`

Литерал `0` -  в контексте указателя литерал `0` специально определен как нулевое значение, и это единственный случай, когда можно присвоить указателю целочисленный литерал.
Кроме того, существует макрос препроцессора с именем `NULL` (определенный в заголовочном файле `<cstddef>`). Этот макрос унаследован от языка Cи. В C++ его использование нежелательно: в отличие от `nullptr`, он не обеспечивает такой же ясной и безопасной типизации. Предпочитайте `nullptr`.

## Указатели и константы

- Неконстантному указателю (`int* ptr`) можно присвоить адрес другого объекта подходящего типа. После этого указатель будет указывать на другой объект.

```cpp
{
    int x { 5 };
    int* ptr { &x };        // ptr — это обычный (неконстантный) указатель
    int y { 6 };
    ptr = &y;               // можно указать на другое значение

    *ptr = 7;               // можно изменить значение по адресу ->  b = 7
 }
 ```

- Указатель на неконстантное значение (например, `int* ptr`) может изменять значение, на которое он указывает. Такие указатели не могут указывать на константное значение.

```cpp
{   const int x { 5 };      // x -> const
    int* ptr { &x };        // ERROR: компиляции: невозможно преобразовать const int* в int*
}
```

- Указатель на константное значение (например, `const int* ptr`) рассматривает это значение как константное при доступе через указатель и не может изменить значение, на которое он указывает. На них могут указывать константные или неконстантные l-значения.

```cpp
{
    const int x{ 5 };
    const int* ptr { &x };  // okay: указатель ptr указывает на "константное целое число"

    *ptr = 6; // ERROR: нельзя изменять константное значение
}

// указатель на const сам по себе не является const (он просто указывает на const-значение)
{
    const int x{ 5 };
    const int* ptr { &x };  // ptr указывает на const int x

    const int y{ 6 };
    ptr = &y;               // ptr указывает на const int y
}

//-------указатель на const может указывать и на неконстантные переменные---
{
    int x{ 5 };             // x не const
    const int* ptr { &x }; // ptr points to a "const int"

    *ptr = 6;   // ERROR: указатель ptr указывает на "константное целое число",
                // поэтому нельзя изменить значение через ptr
    x = 6;
                // okay: значение остается неконстантным при доступе через
                // неконстантный идентификатор x.
}
```

- Постоянный указатель `const int* const ptr` - константный указатель на `const int`: после инициализации указатель нельзя перенаправить на другой объект и изменить объект через этот указатель нельзя.

```cpp
// -------Константные указатели--------------------------
{
    int x{ 5 };
    int* const ptr { &x }; // const после звездочки означает, что это константный указатель

    *ptr = 6; // okay: значение переменной х является неконстантным

    int y{ 6 };
    ptr = &y; // ERROR: После инициализации константный указатель изменить нельзя
}

//-------Константный указатель на константное значение----
{
    int x { 5 };
    const int* const ptr { &x }; // a const указатель на const значение
}
```

| Объявление | Можно изменить адрес указателя? | Можно изменить объект через указатель? |
|---|---:|---:|
| `int* ptr` | Да | Да |
| `const int* ptr` | Да | Нет |

## Передача указателя в функцию

```cpp
#include <iostream>

void printValue(int val) {
    std::cout << "\nwork function: printValue(int val)\n";
    std::cout << val << " в ОП по адресу " << &val << '\n';
}

void printPointer(int*  ptr) {
    std::cout << "\nwork function: printPointer(int* ptr)\n";
    std::cout << "в ОП по адресу "<< ptr << " значение " << *ptr << '\n';
}

int main() {
    int value {42};

    printValue(value);
    printPointer(&value);

    std::cout << '\n';
    return 0;
}
```

```text
/a.out

work function: printValue(int val)
42 в ОП по адресу 0x16ddb299c

work function: printPointer(int* ptr)
в ОП по адресу 0x16ddb29c8 значение 42
```

При передаче указателя по значению копируется значение указателя, а не объект, на который он указывает. Благодаря этому функция может обращаться к исходному объекту через указатель, а при допустимом типе указателя — изменять его.

Когда функция принимает адрес объекта, параметр-указатель позволяет ей работать с самим этим объектом с помощью операции разыменования. Если указатель указывает на доступный для изменения объект через неконстантный тип указателя, функция может изменить этот объект с помощью разыменования.

Если функция не должна изменять передаваемый объект, параметром функции следует сделать указатель на константу:

```cpp
void changeValue(const int* ptr) {
    *ptr = 6; // error: невозможно изменить константное значение
}
```

- Использование ключевого слова `const` для того, чтобы сделать сам указатель — параметр функции — константным, имеет мало практической пользы. Это не влияет на вызывающий код и в основном служит лишь для документирования того, что внутри функции указатель не будет изменён.

- Использование ключевого слова `const` для указания на то, что указатель указывает на константный объект, имеет большое значение. Вызывающему коду важно знать, может ли функция изменить переданный объект.

Если не объявлять параметры-указатели как константные указатели, все случаи использования `const` в их объявлениях будут иметь практический смысл. Если же дополнительно использовать `const` для самих указателей, становится сложнее определить, в каких случаях это ключевое слово действительно важно, а в каких оно избыточно. Что ещё важнее, становится труднее заметить указатели, через которые функция может изменять переданные объекты.

Например:

- Обычные указатели: каждое использование `const` имеет значение - `void foo(const char* source, char* dest, int count);`
   `source` — это указатель на константный объект, а `dest` — указатель на неконстантный объект.

- Константные указатели: среди избыточных `const` - `void foo(const char* const source, char* const dest, int count);`
    здесь сложнее заметить, что `dest` — константный указатель на неконстантный объект. Сам указатель dest нельзя перенаправить на другой объект внутри функции, но объект, на который он указывает, функция по-прежнему может изменять.

>***Рекомендации по стилю***

>- *Предпочитайте указатели на константные объекты (`const T*`) в качестве параметров функций, если функция не должна изменять переданный объект.*
>- *Используйте указатели на неконстантные объекты (`T*`), если функция должна иметь возможность изменять переданный объект.*
>- *Не объявляйте сами указатели-параметры константными (`T* const` или `const T* const`), если для этого нет веских причин.*

## Возврат указателя из функции

При передаче аргумента по значению в параметр функции создаётся копия аргумента. Для базовых типов (копирование которых обходится дёшево) это приемлемо. Но для типов классов (таких как std::string) копирование обычно обходится дорого. Можно избежать дорогостоящего копирования, используя передачу по адресу.

При передаче аргумента по адресу в вызываемой функции создаётся копия адреса аргумента. Аналогичная ситуация возникает при возврате: копия возвращаемого значения передается обратно вызывающей стороне.

Возврат по адресу работает практически идентично возврату по значению, за исключением того, что возвращается указатель на объект, а не сам объект. Нельзя возвращать указатель на локальную автоматическую переменную, если после завершения функции её время жизни заканчивается. Возвращённый указатель станет `висячим`. Возвращать указатель можно на объект, время жизни которого гарантированно продолжается после завершения функции, при условии что соблюдены правила владения и использования этого объекта.

Возврат указателя удобен в случаях, когда функция может вернуть адрес существующего объекта или `nullptr`, обозначающий отсутствие результата.

Главный недостаток возврата по адресу заключается в том, что вызывающей стороне необходимо помнить о проверке `nullptr` перед разыменованием возвращаемого значения, иначе может произойти разыменование нулевого указателя, что приведет к неопределенному поведению (UB).

# Вторая часть — ссылки

### Зачем вообще нужны ссылки и указатели?

```cpp
void increment(int x){
    ++x;
}

int main(){
    int value{10};

    increment(value);

    std::cout << value;
    return 0;
}
```

Результат:

```text
10
```

Почему? Потому что функция получила копию.

```text
main()          │             increment()

value = 10        ──────►     x = 10
                │              │
                │              ++x
                │              │
                │              11
```

Исходный `value` не изменился.

> ***Как сделать так, чтобы функция работала именно с исходным объектом?***

Можно было бы передать функции адрес объекта и обращаться к нему через разыменование.

Но в C++ есть более удобный механизм — **ссылка**.

Прежде чем разбирать синтаксис ссылок и правила их использования, нужно познакомиться с двумя важными категориями выражений в C++: `lvalue` и `rvalue`. Именно от категории выражения зависит, в частности, к чему можно привязать обычную `lvalue`-ссылку.

# 3. `lvalue` и `rvalue` - Категории значений

**Выражение** это «комбинация литералов, переменных, операторов и вызовов функций, которая может быть выполнена для получения единственного значения».

```cpp
#include <iostream>

int main(){
    std::cout << 2 + 3 << '\n'; //  2 + 3 - это выражение

    return 0;
}
```

Для определения того, как должны оцениваться выражения и где их можно использовать, все выражения в C++ имеют два свойства: тип и категорию значения.

***Тип выражения*** эквивалентен типу значения, объекта или функции, которые получаются в результате вычисления выражения. Например:

```cpp
#include <iostream>

int main(){
    int v1 { 12 / 4 };     // int / int => int
    double v2 { 12.0 / 4 };   // double / int => double

    return 0;
}
```

Компилятор может использовать тип выражения для определения того, является ли выражение допустимым в данном контексте.

```cpp
#include <iostream>

void print(int x){
    std::cout << x << '\n';
}

int main(){
    print("foo"); // error: void print(int)

    return 0;
}
```

Тип выражения должен определяться во время компиляции (иначе проверка типов и вывод типов не будут работать) — однако значение выражения может определяться либо во время компиляции (если выражение является `constexpr`), либо во время выполнения (если выражение не является `constexpr`).

***Категория значения выражения (value category)***

```cpp
int main(){
    int x{};

    x = 5;   // ok
    5 = x;   // error

    return 0;
}
```

Категория значений выражения (или подвыражения) указывает, преобразуется ли выражение в значение, функцию или объект какого-либо типа.

>*До C++11 существовали только две возможные категории значений: `lvalue` и `rvalue`. В C++11 были добавлены три дополнительные категории значений ( `glvalue`, `prvalue`, и `xvalue`) для поддержки новой функции, называемой `move semantics`.
Семантику перемещения (и три дополнительные категории значений) рассмотрим в будущем.*

```cpp
    int x { 10 };
    int y { x };    // x  - lvalue выражение
```

```text
x;       // lvalue
y;       // lvalue
10;      // rvalue
x + y;   // rvalue
x * 2;   // rvalue
```

- `x` обозначает существующий объект, которому можно присвоить новое значение.
- `10` — литерал
- `x + y` — результат вычисления. Это не самостоятельный изменяемый объект, которому можно присвоить значение.

`lvalue` — это выражение, которое обозначает конкретный объект или функцию, а `rvalue` — выражение, которое не является `lvalue`. Обычно оно представляет результат вычисления или временный объект.

`lvalue` ​​делятся на два подтипа:
- ***изменяемое `lvalue`***
- ***неизменяемое `lvalue`***.

```cpp
    int x{};
    const double d{};

    int y { x }; // x изменяемое lvalue выражение
    const double e { d }; // d неизменяемое lvalue выражение
}
```

`const` не меняет категорию выражения: `d` по-прежнему `lvalue`, но через него нельзя изменить объект.

Полный список выражений `lvalue` и `rvalue` можно найти [здесь](https://ru.cppreference.com/cpp/language/value_category).

# 4. Ссылки `lvalue references`

В C++ ***ссылка*** — это псевдоним для существующего объекта. После определения ссылки любая операция над ней применяется к объекту, на который она ссылается. Это означает, что можно использовать ссылку для чтения или изменения объекта, на который она ссылается.

```cpp
#include <iostream>

int main(){
    int value { 10 };

    int& x { value };

    x = 7;

    std::cout << x << '\n';  // 7
    return 0;
}
```

`x` — это ссылка на `value`.

Ссылка объявляется с помощью оператора `&`

объект один:

```text
        ┌─────────┐
        │ value   │
        │   10    │
        └─────────┘
          ▲     ▲
          │     │
        value   х
```

## Типы ссылок `lvalue`

Подобно тому, как тип объекта определяет, какое значение он может хранить, тип ссылки определяет, на какой тип объекта она может ссылаться. Типы ссылок на значения (lvalue) можно определить с помощью амперсанда (&) в спецификаторе типа:

```cpp
int        // фундаментальный тип int (не ссылка)
int&       // lvalue-ссылка на объект типа int
double&    // lvalue-ссылка на объект типа double
const int& // lvalue-ссылка на объект типа const int
```

>***Ссылка позволяет обращаться к существующему объекту через другое имя.***

```cpp
#include <iostream>

int main()
{
    int x { 5 };
    int& ref { x };
    std::cout << x << ref << '\n';

    x = 6;
    std::cout << x << ref << '\n';

    ref = 7;
    std::cout << x << ref << '\n';

    return 0;
}
```
<!--
```text
55
66
77

```
-->

Ссылка должна быть инициализирована при объявлении: при создании ссылки необходимо указать объект, с которым она будет связана.

`lvalue-ссылка` обычно связывается с объектом подходящего типа. Например, `int&` может ссылаться на объект типа `int`.

Eсли тип ссылки (например, `int&`) не совпадает с типом связываемого объекта (например, `int`), преобразование здесь не применяется (даже тривиальное преобразование) — разница в типах обрабатывается в процессе инициализации ссылки.

>**Ссылка (обычно) будет связываться только с объектом, соответствующим типу, на который она ссылается.**

>**Ссылки нельзя переназначить (изменить, чтобы они ссылались на другой объект).**

```cpp
    int x { 5 };
    int y { 10 };

    int& ref { x };

    ref = y;    // присваивает x значение y, но не меняет связь ref (ref -> x)
```

Время жизни ссылки и время жизни объекта, на который она ссылается, **независимы**. Другими словами, верны оба следующих утверждения:

- Ссылка может быть уничтожена раньше, чем объект, на который она ссылается.
- Объект, на который делается ссылка, может быть уничтожен до того, как будет уничтожена ссылка.

Если ссылка уничтожается раньше, чем объект, на который она ссылается, это никак не влияет на объект, на который она ссылается.

```cpp
#include <iostream>

int main(){
    int x { 5 };

    {
        int& ref { x };
        std::cout << ref << '\n';
    }

    std::cout << x << '\n';

    return 0;
}
```

ссылка ref выходит из области видимости раньше, чем объект x уничтожается. Это безопасно. Уничтожение ссылки никак не влияет на x.

## Висячие ссылки

Когда объект, на который делается ссылка, уничтожается и остается ссылка на объект, которого больше не существует. То такая ссылка называется `висячей ссылкой`. Доступ к висячей ссылке приводит к неопределенному поведению (UB - *undefined behavior*).

```cpp
int& getValue(){
    int value { 10 };
    return value; // error: время жизни value заканчивается при выходе из функции
}
```

Функция возвращает ссылку на локальную переменную, которая будет уничтожена к моменту использования результата. Такая ссылка становится **висячей**.

***Ссылки не являются объектами.***

В C++ ссылка не является самостоятельным объектом языка: она представляет собой другое имя уже существующего объекта. Поэтому к ссылке нельзя относиться как к отдельной переменной, которая хранит собственное значение. Компилятор сам определяет, как реализовать обращение через ссылку.

```cpp
int var{};
int& ref1{ var };  // ссылка на lvalue, связанная с var
int& ref2{ ref1 }; // ссылка на lvalue, связанная с var
```

Если инициализировать ссылку другой ссылкой, новая ссылка связывается с тем же объектом, с которым связана исходная ссылка. Ссылки на ссылки в обычных объявлениях таким способом не создаются.

Ссылка на ссылку (например на `int`) имела бы синтаксис `int&&` — но поскольку C++ не поддерживает ссылки на ссылки, этот синтаксис был перепрофилирован в C++11 для обозначения ссылки на `rvalue`.

## Ссылки на `const`

```cpp
#include <iostream>

int main()
{
    const int x { 5 };
    const int& ref { x };

    std::cout << ref << '\n';

    ref = 6;          // error:

    return 0;
}
```

```cpp
#include <iostream>

int main(){
    int x { 5 };
    const int& ref { x };   // ok

    std::cout << ref << '\n';
    ref = 7;                // error
    x = 6;                  // ok
    return 0;
}
```

`const` в объявлении `const int&` запрещает изменять объект через эту ссылку. Это не обязательно означает, что сам объект константный: если он был объявлен как обычный `int`, его можно изменить другим способом — например, непосредственно через имя `x`.

## Передача по ссылке

```cpp
#include <iostream>

void printAddresses(int val, int& ref)
{
    std::cout << "Адрес параметра значения: " << &val << '\n';
    std::cout << "Адрес параметра ссылки: " << &ref << '\n';
}

int main()
{
    int x { 5 };
    std::cout << "Адрес x: " << &x << '\n';
    printAddresses(x, x);

    return 0;
}
```

```cpp
#include <iostream>

void increment(int& x){
    ++x;
}

int main() {
    int value{10};

    increment(value);
    std::cout << value << '\n';
```

Передача по константной ссылке обеспечивает то же основное преимущество, что и передача по неконстантной ссылке (избегая создания копии аргумента), а также гарантирует, что функция не сможет изменить значение, на которое она ссылается.

```cpp
void addOne(const int& ref){
    ++ref; // error: ссылка является константой
}
```

>***Предпочтительнее передавать аргументы по константной ссылке, а не по неконстантной, если только у вас нет для этого веских причин (например, функция должна изменять значение аргумента).***

### *Передача аргументов другого типа в параметр, являющийся константным `lvalue`-ссылкой.*

Константная ссылка на `lvalue` может связываться со значением другого типа, если это значение преобразуется в тип ссылки. Преобразование создает временный объект, к которому затем может быть привязан параметр-ссылка.

Основная причина, по которой это разрешено, заключается в том, чтобы можно было передавать значение в качестве аргумента либо параметру значения, либо параметру константной ссылки совершенно одинаковым образом:

```cpp
#include <iostream>

void printVal(double d)
{
    std::cout << d << '\n';
}

void printRef(const double& d)
{
    std::cout << d << '\n';
}

int main()
{
    printVal(5); // 5 преобразуется во временный тип double, копируется в параметр d
    printRef(5); // 5 преобразуется во временный тип double, связывается с параметром d

    return 0;
}
```

При передаче будет создана копия, поэтому, если сначала произойдет преобразование (в результате чего появится дополнительная копия), это редко становится проблемой (и компилятор, скорее всего, оптимизирует одну из двух копий).

Однако передача по ссылке используется, когда не надо создавать копию. Если сначала происходит преобразование, это, как правило, приводит к созданию (возможно, дорогостоящей) копии, что может быть неоптимальным решением.

>***Предупреждение:
При передаче по ссылке убедитесь, что тип аргумента соответствует типу ссылки, иначе это приведет к неожиданному (и, возможно, дорогостоящему) преобразованию.***

## Возврат по ссылке и возврат по адресу

При возврате по значению: копия возвращаемого значения передается обратно вызывающей стороне. Если тип возвращаемого значения функции является типом класса (большой объект), это может быть затратно.

Когда передаётся тип класса обратно вызывающей стороне, можно вернуть значение по ссылке. ***Возврат по ссылке*** возвращает ссылку, связанную с возвращаемым объектом, что позволяет избежать копирования возвращаемого значения. Для возврата по ссылке определяется возвращаемое значение функции как ссылочный тип.

Но при этом необходимо, чтобы  объект, возвращаемый по ссылке, существовал после завершения работы функции.

Вызывающая сторона может изменять значения посредством ссылки.

Когда аргумент передается в функцию по неконстантной ссылке, функция может использовать эту ссылку для изменения значения аргумента.

Аналогично, когда функция возвращает неконстантную ссылку, вызывающая сторона может использовать эту ссылку для изменения возвращаемого значения.

```cpp
#include <iostream>

int& max(int& x, int& y){
    return (x > y) ? x : y;
}

int main(){

    int a{ 5 };
    int b{ 6 };

    max(a, b) = 7; // устанавливает большее из значений a или b равным 7

    std::cout << a << b << '\n';

    return 0;
}
```

В приведенной программе выражение max(a, b) = 7 фактически сводится к b = 7.

```text
57
```

***Возврат по адресу*** работает практически идентично возврату по ссылке, за исключением того, что возвращается указатель на объект, а не ссылка на него. Возврат по адресу имеет тот же основной недостаток, что и возврат по ссылке — возвращаемый по адресу объект должен существовать за пределами области видимости функции, возвращающей адрес, иначе вызывающая сторона получит висячий указатель.

Главное преимущество возврата по адресу перед возвратом по ссылке заключается в том, что функция может вернуть значение, `nullptr` если нет допустимого объекта для возврата. Например, предположим, у нас есть список студентов, которых необходимо найти. Если нужный студент в списке, можно вернуть указатель на объект, представляющий соответствующего студента. Если нет ни одного соответствующего студента, можно вернуть `nullptr`, значение, указывающее на то, что объект соответствующего студента не найден.

# 5. Ссылка vs Указатель — сравнение

| Ссылка | Указатель |
| :------------- | :------------- |
| Должна быть привязана к объекту | Может быть `nullptr` |
| Обычно не переназначается | Может указывать на разные объекты |
| Используется как имя объекта | Нужно разыменование `*` |
| `ref = value` изменяет объект | `*ptr = value` изменяет объект |
| Обычно не проверяют на `null` | Нужно учитывать возможность `nullptr` |

Если ссылки удобнее, зачем учить указатели?

Потому что указатели позволяют делать то, что обычная ссылка не позволяет или для чего указатель является естественным инструментом:

- явно хранить адрес;
- менять объект, на который указываем;
- иметь состояние `nullptr`;
- работать с динамической памятью;
- перемещаться по массивам;
- строить структуры данных;
- работать с низкоуровневыми API;
- передавать опциональный объект;
