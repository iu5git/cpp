## 1. Перечисления `enum`

В C++ содержится множество полезных базовых и составных типов данных. Но этих типов не всегда достаточно для тех задач, которые нам необходимо выполнить.

Например, предположим, вы пишете программу, которой нужно отслеживать, красное, жёлтое или зелёное яблоко, или время суток. Если бы были доступны только базовые типы данных, как бы вы это сделали?

Цвет можно хранить как целочисленное значение, используя неявное сопоставление ( 0 = ночь, 1 = утро, 2 = день, 3 = вечер):

```cpp
int main(){
    int timeDayNight{ 0 };
    int timeDayMorning{ 1 };
    ...
    return 0;
}
```

Mожно избавиться от «магических чисел», используя символические константы:

```cpp
constexpr int night{ 0 };
constexpr int morning{ 1 };
constexpr int afternoon{ 2 };
constexpr int evening{ 3 };

int main()
{
    int timeDayNight{ night };
    int timeDayMorning{ morning };
    ...
    return 0;
}
```

Mожно сделать эту программу немного понятнее, используя псевдоним типа:

```cpp
using TimeDay = int; // псевдоним типа с именем timeDay

constexpr TimeDay night{ 0 };
constexpr TimeDay morning{ 1 };
constexpr TimeDay afternoon{ 2 };
constexpr TimeDay evening{ 3 };


int main(){
    TimeDay timeDayNight{ night };
    TimeDay timeDayMorning{ morning };
    ...
    return 0;
}
```

Tеперь у типа есть уникальное имя `TimeDay` по которому можно найти набор соответствующих символических констант.

`TimeDay` является всего лишь псевдонимом для `int`, остается проблема, заключающаяся в том, что ничто не обеспечивает правильного использования этих символических констант времени суток.

```cpp
    TimeDay day{ 8 }; // синтаксически корректно, семантически бессмысленно
```

Кроме того, при отладке любую из этих переменных в отладчике, отразится только целочисленное значение (например, 3), а не его символическое значение ( evening ), что может затруднить определение корректности нашей программы.

Mожно сделать лучше.

В качестве примера рассмотрим `bool` тип. У `bool` всего два определенных значения: `true` и `false`. Можно использовать `true` или `false` напрямую (как литералы), или же можем создать экземпляр `bool`-объекта, который будет содержать любое из этих значений. Кроме того, компилятор способен отличать `bool` от других типов. Это означает, что можно перегружать функции и настраивать их поведение при передаче `bool` значения.

>***Перечисление*** (также называемое перечисляемым типом или enum ) — это составной тип данных , значения которого ограничены набором именованных символических констант (называемых перечислителями).

В C++ поддерживаются два типа перечислений:

- ***перечисления без области видимости***
- ***перечисления с областью видимости***

Поскольку перечисления являются программно-определяемыми типами, каждое перечисление должно быть полностью определено, прежде чем можно его использовать (предварительного объявления недостаточно).

## 2. Перечисления без области видимости (`enum`)

```cpp
// Определите новое перечисление без области видимости с именем `TimeDay`
enum TimeDay{
    // элементы перечисления
    // Эти символические константы определяют все возможные значения, которые может принимать данный тип
    // Каждый элемент перечисления разделяется запятой, а не точкой с запятой
    night,
    morning,
    afternoon,
    evening,  // Замыкающая запятая необязательна, но рекомендуется
}; // Определение перечисления должно заканчиваться точкой с запятой

int main(){

    TimeDay timeDayNight{ night };
    TimeDay timeDayMorning{ morning };
    TimeDay timeDayAfternoon{ afternoon };
    TimeDay timeDayEvening{ evening };

    TimeDay day { midday }; // error: midday не является элементом перечисления TimeDay
    TimeDay h { 2 };       // error: 2 не является элементом перечисления TimeDay

    return 0;
}
```

### `enum` типы — это различные типы

Каждый создаваемый перечисляемый тип считается отдельным типом, то есть компилятор может отличить его от других типов (в отличие от псевдонимов типов).

Поскольку перечисляемые типы являются различными, перечислители, определенные как часть одного перечисляемого типа, не могут использоваться с объектами другого перечисляемого типа:

```cpp
enum Pet{
    cat,
    dog,
    pig,
    whale,
};

enum Color{
    black,
    red,
    blue,
};

int main(){
    Pet myPet { black }; // error компиляции: black не является элементом перечисления Pet
    Color shirt { pig }; // error компиляции: не является элементом перечисления Color

    return 0;
}
```

### Применение перечислений на практике

Поскольку перечислители являются описательными, они полезны для улучшения документирования кода и его читаемости. Перечисляемые типы лучше всего использовать, когда у вас есть небольшой набор связанных констант, и объектам нужно хранить только одно из этих значений одновременно.

К общепринятым обозначениям относятся дни недели, стороны света и масти в колоде карт:

```cpp
enum DaysOfWeek{
    sunday,
    monday,
    tuesday,
    wednesday,
    thursday,
    friday,
    saturday,
};

enum CardinalDirections{
    north,
    east,
    south,
    west,
};

enum CardSuits{
    clubs,
    diamonds,
    hearts,
    spades,
};
```

### Проблема имён в `enum` без области видимости

Перечисления без области видимости называются так потому, что они помещают имена перечислителей в ту же область видимости, что и само определение перечисления (в отличие от создания новой области видимости, как это делает пространство имен).

```cpp
enum Color{ // Это перечисление определено в global namespace
    red, // поэтому red помещается в  global namespace
    green,
    blue,
};

int main(){
    Color apple { red };

    return 0;
}
```

Перечисление `Color` определено в глобальной области видимости. Следовательно, все имена перечислений ( red, green, и blue) также попадают в глобальную область видимости. Это загрязняет глобальную область видимости и значительно повышает вероятность конфликтов имен.

Одним из следствий этого является то, что имя перечислителя нельзя использовать в нескольких перечислениях в рамках одной и той же области видимости:

```cpp
enum Color{
    red,
    green,
    blue, // blue находится в global namespace
};

enum Feeling{
    happy,
    tired,
    blue, // error: конфликт имен с объявленным выше blue
};

int main(){
    Color apple { red }; //
    Feeling me { happy }; // I'm happy right now (even though my program doesn't compile)

    return 0;
}
```

В приведенном выше примере оба не ограниченных областью видимости перечисления ( `Color` и `Feeling`) помещают перечисления с одинаковым именем `blue` в глобальную область видимости. Это приводит к конфликту имен и последующей ошибке компиляции.

Удачный вариант — поместить перечисляемый тип внутрь чего-либо, что обеспечивает отдельную область видимости, например, пространства имен:

```cpp
namespace Color{
    enum Color{
        red,
        green,
        blue,
    };
}

namespace Feeling{
    enum Feeling{
        happy,
        tired,
        blue,
    };
}

int main(){
    Color::Color paint{ Color::blue };
    Feeling::Feeling me{ Feeling::blue };

    return 0;
}
```

Это означает, что теперь нам необходимо добавлять префикс к именам перечисления и перечислителя, указывающий на область действия.

### Преобразования целочисленных значений перечислителей без области действия

Перечислители являются символическими константами.

При определении перечисления каждому перечислителю автоматически присваивается целочисленное значение в зависимости от его позиции в списке перечислителей. По умолчанию первому перечислителю присваивается целочисленное значение 0, а каждому последующему перечислителю присваивается значение на единицу больше:

```cpp
enum Color{
    black,   // 0
    red,     // 1
    blue,    // 2
    green,   // 3
    white,   // 4
    cyan,    // 5
    yellow,  // 6
    magenta, // 7
};

int main()
{
    Color shirt{ blue }; // shirt на самом деле хранит целочисленное значение 2

    return 0;
}
```

Можно явно задать значения перечислителей. Эти целочисленные значения могут быть положительными или отрицательными и могут иметь то же значение, что и другие перечислители. Любым неопределенным перечислителям присваивается значение на единицу больше, чем у предыдущего перечислителя.

```cpp
enum Animal{
    cat = -3,    // значения могут быть отрицательными
    dog,         // -2
    pig,         // -1
    horse = 5,
    giraffe = 5, // имеет то же значение, что и horse
    chicken,     // 6
};
```

### Инициализация значения перечисления

Перечисление инициализируется значением 0, даже если нет соответствующего перечислителя с таким значением.

```cpp
#include <iostream>

enum Animal{
    cat = -3,    // -3
    dog,         // -2
    pig,         // -1
    // в этом списке нет элемента перечисления со значением 0
    horse = 5,   // 5
    giraffe = 5, // 5
    chicken,     // 6
};

int main()
{
    Animal a {};
    std::cout << a; //  0

    return 0;
}
```

По этой причине целесообразно выбрать в качестве перечислителя со значением 0 то значение, которое наилучшим образом соответствует значению по умолчанию для вашего перечисления.

### Размер перечисления и его базовый тип (underlying type)

Перечислители имеют значения целочисленного типа. Большинство компиляторов будут использовать `int` в качестве базового типа

### Преобразование целого числа в перечислитель без области видимости

Хотя компилятор неявно преобразует перечисление без области видимости в целое число, он не преобразует целое число в перечисление без области видимости. Следующий код приведет к ошибке компиляции:

```cpp
enum Pet {
    cat,        //0
    dog,        //1
    pig,        //2
    whale,      //3
};

int main(){
    Pet pet { 2 }; // error компиляции: целочисленное значение 2 не будет неявно преобразовано в тип Pet
    pet = 3;       // error компиляции: целочисленное значение 3 не будет неявно преобразовано в тип Pet

    return 0;
}
```

```cpp
enum Pet {
    cat, // assigned 0
    dog, // assigned 1
    pig, // assigned 2
    whale, // assigned 3
};

int main()
{
    Pet pet { static_cast<Pet>(2) };
    pet = static_cast<Pet>(3);       // our pig evolved into a whale!

    return 0;
}
```

Можно безопасно преобразовывать в `static_cast` любое целочисленное значение, представленное перечислителем целевого перечисления. Поскольку `Pet` перечисление имеет перечислители со значениями 0, 1, 2, и 3, преобразование целочисленных значений 0, 1, 2 и 3 с помощью `static_cast<Pet>` является допустимым».

Начиная с C++17, если у перечисления без области видимости явно указан базовый класс, компилятор позволит инициализировать такое перечисление целочисленным значением:

```cpp
enum Pet: int {
    cat,
    dog,
    pig,
    whale,
};

int main()
{
    Pet pet1 { 2 }; // ok: разрешено в C++17 при явном базовом типе"
    Pet pet2 (2);   // error компиляции:
    Pet pet3 = 2;   // error компиляции:

    pet1 = 3;       // error компиляции:
    return 0;
}
```

## 3. Перечисления с ограниченной областью видимости (`enum class`)

### Ограниченные перечисления

Перечисления с областью видимости работают аналогично перечислениям без области видимости, но имеют два основных отличия: они **не преобразуются неявно в целые числа**, и перечислители **помещаются только в область видимости перечисления** (а не в область видимости, где определено перечисление).

Для создания перечисления с ограниченной областью видимости используются ключевые слова `enum class`. Остальная часть определения перечисления с ограниченной областью видимости аналогична определению перечисления без области видимости.

```cpp
#include <iostream>

    enum class Color{
        red,
        blue,
    };

    enum class Fruit{
        banana,
        apple,
    };

int main(){
    Color color { Color::red };
    Fruit fruit { Fruit::banana };

    if (color == fruit) // error компиляции: типы строго изолированы друг от друга и не приводятся неявно к int
        std::cout << "color and fruit are equal\n";
    else
        std::cout << "color and fruit are not equal\n";

    return 0;
}
```

В этой программе возникает ошибка компиляции поскольку перечисление с ограниченной областью видимости не преобразуется ни в какой тип, который можно сравнить с другим типом.

Иногда возникает необходимость рассматривать перечислитель с областью видимости как целочисленное значение. В таких случаях можно явно преобразовать перечислитель с областью видимости в целое число, используя `static_cast`. В C++23 лучшим вариантом является использование метода `std::to_underlying()` (определенного в заголовочном файле `<utility>`), который преобразует перечислитель в значение базового типа перечисления.

Это один из лучших способов использовать `enum class`.

```cpp
#include <iostream>

enum class Direction{
    Up,
    Down,
    Left,
    Right
};

int main(){
    Direction direction{Direction::Left};

    switch (direction)
    {
        case Direction::Up:
            std::cout << "up";
            break;

        case Direction::Down:
            std::cout << "down";
            break;

        case Direction::Left:
            std::cout << "left";
            break;

        case Direction::Right:
            std::cout << "right";
            break;
    }

    return 0;
}
```
