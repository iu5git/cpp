Функция позволяет дать имя отдельному фрагменту программы, определить его один раз и вызывать там, где он нужен.

  • знать, что такое стек вызовов;

  • знать, что такое перегрузка функций;

Зачем нужны функции

Допустим, нужно написать программу, которая работает с числами:

  • проверяет, является ли число четным;
  • находит максимум;
  • вычисляет сумму;
  • выводит результат.

Можно всё написать внутри main().

Например:

int main() {

    int a{10};
    int b{20};

    if (a % 2 == 0) {
        // ...
    }

    if (b % 2 == 0) {
        // ...
    }

    // еще код
    return 0;
}

Очень быстро main() превращается в длинный и плохо читаемый код.

Возникает естественная идея:

Давайте отдельную операцию оформим как самостоятельную часть программы.

Например:

bool isEven(int number) {
    return number % 2 == 0;
}

Теперь можно написать:

if (isEven(a)) {
    // ...
}

и:

if (isEven(b)) {
    // ...
}

1. Функции

Функция — именованный фрагмент программы, который выполняет определенную задачу и может быть вызван из другого места программы.

У функции есть:

  • имя;
  • параметры;
  • возвращаемый тип;
  • тело.

Например:

int add(int a, int b) {
    return a + b;
}

Разберем:

int
│
└── тип возвращаемого значения

add
│
└── имя функции

(int a, int b)
│
└── параметры

{ ... }
│
└── тело функции

Объявление (declaration) и определение (definition) функций

Определение

содержит её реализацию — тело функции, а также её заголовок:

int add(int a, int b) {
    return a + b;
}

Объявление

сообщает компилятору о существовании функции и её интерфейсе.

int add(int a, int b);

Точка с запятой здесь обязательна.

Зачем нужно объявление?

Рассмотрим:

int main() {
    int result{add(2, 3)};
}

int add(int a, int b) {
    return a + b;
}

Компилятор, обрабатывая main(), еще не знает о функции add.

Поэтому можно заранее написать:

int add(int a, int b);

int main() {
    int result{add(2, 3)};
    return 0;
}

int add(int a, int b) {
    return a + b;
}

Такое объявление функции, размещённое до её использования, часто называют предварительным объявлением (forward declaration).

Позже, когда будем говорить о многофайловых программах, эта идея станет основой заголовочных файлов.

Параметры

Параметры позволяют передавать функции данные.

int square(int x) {
    return x * x;
}

Вызов:

int result{square(5)};

При передаче по значению параметр функции получает копию значения аргумента.

Внутри:

x = 5

результат:

25

Параметры и аргументы

Важно использовать правильные термины.

В объявлении функции:

int square(int x)

x — параметр.

При вызове:

square(5);

5 — аргумент.

Можно сформулировать:

Параметр — имя, указанное в списке параметров функции и используемое внутри функции для обращения к переданному значению или объекту.

Аргумент — выражение, указанное при вызове функции.

Несколько параметров

int max(int a, int b) {
    if (a > b) {
        return a;
    }

    return b;
}

Вызов:

int result{max(10, 20)};

Получим:

20

Возвращаемое значение

Функция может возвращать результат.

int multiply(int a, int b) {
    return a * b;
}

Ключевое слово: return означает:

return завершает выполнение текущей функции. В функции с возвращаемым типом он может одновременно передать значение вызывающему коду.

Например:

    result = multiply(x, y);

После выполнения: если x равно 4, y равно 5 тогда result будет равен 20

Что происходит после return

Например:

int test() {
    return 10;

    std::cout << "Hello";
}

Строка std::cout << "Hello"; никогда не выполнится.

return завершает функцию.

Тип void

Не каждая функция должна возвращать значение.

Например:

void printHello() {
    std::cout << "Hello\n";
}

void означает:

что функция не возвращает значение вызывающему коду.

Вызов:

printHello();

Можно использовать return без значения:

void printNumber(int x) {
    if (x < 0) {
        return;
    }

    std::cout << x;
}

В данном примере функция завершится если значение переменной x меньше 0.

2. Локальные переменные и область видимости

int add(int a, int b) {
    int result{a + b};

    return result;
}

int main()
{
    std::cout << result; // ошибка
}

result — локальная переменная, объявленная внутри блока тела функции add(). Переменная с именем result доступна только внутри этого блока.

Scope (область видимости) — часть программы, в которой имя доступно.

Например:

int main() {
    int x{10};

    {
        int y{20};

        std::cout << x;
        std::cout << y;
    }

    std::cout << x;

    // y здесь уже недоступна
}

3. Статические локальные переменные

Обычная локальная переменная:

void foo()
{
    int count{0};
    ++count;

    std::cout << count << '\n';
}

Каждый вызов функции создает новую переменную count.

Если вызвать:

foo();
foo();
foo();

получим:

1
1
1

Теперь:

void foo()
{
    static int count{0};
    ++count;

    std::cout << count << '\n';
}

Результат:

1
2
3

Почему?

static для локальной переменной означает, что объект имеет статическую длительность хранения: он создаётся один раз и существует до завершения программы, сохраняя своё значение между вызовами функции.

Область видимости и время жизни — это не одно и то же.

В примере:

void foo()
{
    static int count{0};
}

переменная count:

  • видна только внутри foo();
  • объект с локальным static существует до завершения программы, но его инициализация выполняется при первом прохождении объявления.

То есть:

scope - где переменную можно использовать

lifetime - как долго переменная существует

Где полезен static

Например, нужно посчитать количество вызовов функции:

void printCallCount()
{
    static int count{0};

    ++count;

    std::cout << "Вызов № " << count << '\n';
}

Это демонстрационный пример.

В реальном современном коде глобальное состояние и скрытое состояние функций нужно использовать осторожно.

3. Передача параметров

  • Передача по значению
  • Передача по ссылке — первое знакомство.
  • Передача по указателю — будет рассмотренно после изучения указателей

Передача по значению

void increment(int x) {
    ++x;
}

Вызов:

int a{10};

increment(a);

std::cout << a;

Что получим?

10

Почему?

Потому что функция получила копию значения a.

Можно представить:

main():

a = 10
 │
 │ копирование
 ▼
increment():

x = 10

После:

++x;

получается:

x = 11

но исходный a остается:

a = 10

Ссылка — первое знакомство

void increment(int& x) {
    ++x;
}

Теперь:

int a{10};

increment(a);

std::cout << a;

получим:

11

Почему?

Потому что x — ссылка на исходный объект.

Подробно ссылки будут рассмотрены на лекции 6.

способ передачи параметра влияет на то, работает ли функция с копией или с исходным объектом.

5. Стек вызовов

Например:

int square(int x) {
    return x * x;
}

int main() {
    int a{5};

    int result{square(a)};
    return 0;
}

Упрощенно можно представить:

┌─────────────────────┐
│ square()            │
│ x = 5               │
└─────────────────────┘
          ↑
          │
┌─────────────────────┐
│ main()              │
│ a = 5               │
│ result = ?          │
└─────────────────────┘

В упрощённой модели вызов функции связан с созданием кадра стека, в котором хранится часть данных и служебной информации, необходимой для выполнения вызова.

После завершения вызова соответствующий кадр стека перестаёт использоваться.

6. Перегрузка функций

В C++ можно определить несколько функций с одним именем, если их списки параметров различаются так, чтобы вызов можно было однозначно сопоставить с одной из перегрузок.

Только возвращаемый тип не учитывается для различения перегрузок.

Например:

int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}

Теперь:

add(2, 3);

использует первую функцию.

А:

add(2.5, 3.5);

вторую.

Зачем нужна перегрузка?

Позволяет использовать одно понятное имя для одной логической операции.

Без перегрузки пришлось бы писать:

addInt()
addDouble()
addFloat()

Перегрузка позволяет:

add()

Что нельзя?

Нельзя перегружать функции только по возвращаемому типу.

Возвращаемый тип не входит в список параметров, по которому C++ выбирает перегрузку.

Например:

int getValue();
double getValue();

Так нельзя.

Почему?

Потому что при вызове:

int x = getValue();
double y = getValue();

компилятор не знает, какую функцию выбрать - это ошибка компиляции

7. Рекурсия

Теперь интересный пример.

Функция может вызвать сама себя.

void countDown(int n) {
    if (n <= 0) {
        return;
    }

    std::cout << n << '\n';

    countDown(n - 1);
}

Вызов:

countDown(3);

Получим:

3
2
1

Как работает рекурсия?

Первый вызов:

countdown(3)

вызывает:

countdown(2)

который вызывает:

countdown(1)

который вызывает:

countdown(0)

Теперь срабатывает условие остановки.

Базовый случай

В рекурсивной функции обязательно должно быть условие завершения.

Например:

if (n <= 0) {
    return;
}

Это называется базовым случаем.

Без него:

void f() {
    f();
}

Если рекурсивный вызов не приводит к достижению условия завершения, рекурсия не завершится.

При достаточно глубокой рекурсии обычно происходит переполнение стека вызовов.

Рекурсия и стек

Здесь очень удобно связать две темы.

При:

countDown(3)

условно:

┌─────────────┐
│ countdown(1)│
├─────────────┤
│ countdown(2)│
├─────────────┤
│ countdown(3)│
├─────────────┤
│ main        │
└─────────────┘

Каждый вызов создает новый контекст.

Когда функция завершается, контекст удаляется.

8. assert()

Теперь вводим важный инструмент проверки предположений программы.

#include <cassert>

Например:

void processAge(int age) {
    assert(age >= 0 && "Возраст не может быть отрицательным!");
    ...
}

Здесь программист утверждает:

В момент вызова функции age должен быть неотрицательным.

Как работает assert

Если условие истинно:

assert(age >= 0);

ничего особенного не происходит.

Если условие ложно:

age < 0

программа аварийно завершается и сообщает информацию о месте, где сработало утверждение.

Важное различие

assert() — не обычная обработка ошибок для пользователя.

Он предназначен прежде всего для обнаружения ошибок в логике программы и проверки предположений программиста.

Например:

assert(index >= 0);

Это не означает:

«Пользователь ввел неправильное значение, покажем ему сообщение».

Это означает:

«Программист считает, что здесь index уже должен быть неотрицательным. Если это не так — в программе есть проблема».

Важно: assert предназначен для проверок, которые нужны во время разработки. При определении макроса NDEBUG проверки assert отключаются.

9. Атрибуты функций

  • общий синтаксис [[...]]
  • [[nodiscard]]
  • [[maybe_unused]]
  • [[deprecated]]
  • обзор [[fallthrough]]
  • обзор [[noreturn]]

В современном C++ атрибуты записываются в двойных квадратных скобках: [[attribute]]

Они позволяют сообщить компилятору или другим инструментам дополнительную информацию о сущности программы.

nodiscard

Результат функции желательно не игнорировать.

Например:

[[nodiscard]] int calculateSum(int a, int b) {
    return a + b;
}

Если написать:

calculateSum(10, 20);

компилятор может предупредить:

warning: ignoring return value

[[maybe_unused]]

Сообщает компилятору, что функция, переменная или другой объект может намеренно не использоваться, и предупреждение об этом не требуется.

Особенно полезно в условной компиляции и коде, где значение используется только в некоторых конфигурациях.

например:

[[maybe_unused]] void debugFunction() {
    //...
}

[[deprecated]]

Предупреждение компилятора.

[[deprecated]] void oldFunction() {
    //...
}

Теперь: oldFunction();

может вызвать предупреждение компилятора.

Можно даже написать сообщение:

[[deprecated("Use newFunction() instead")]] void oldFunction(){
    //...
}

старая функция
      ↓
ещё существует
      ↓
но использовать её больше не рекомендуется

Aтрибуты используются не только для компилятора, но и как часть документации намерений программиста.

[[fallthrough]]

switch (value) {
case 1:
    doSomething();
    [[fallthrough]];

case 2:
    doSomethingElse();
    break;
}

Он сообщает: что, переход из одного case в следующий сделан намеренно.

[[noreturn]]

Cообщает, что функция не возвращает управление вызывающему коду.

[[noreturn]] void fatalError() {
    std::cerr << "Fatal error\n";
    std::exit(1);
}

Важное различие: атрибут ≠ комментарий

Комментарий:

// Не забыть проверить результат!
int calculate();

Компилятор ничего с этим не делает.

А:

[[nodiscard]] int calculate();

уже является частью программы, которую понимает компилятор.

То есть:

комментарий
   ↓
для человека

[[nodiscard]]
   ↓
информация для компилятора
+ намерение программиста

В современном C++ существуют и другие стандартные атрибуты, например [[likely]] и [[unlikely]], которые позволяют сообщить о предполагаемой вероятности ветвления. Но это уже тема оптимизации, и сейчас нам достаточно знать, что атрибутов много и они имеют разные назначения.

И ещё один важный момент — стандарт

[[...]] — стандартный синтаксис атрибутов C++.

Есть нестандартные атрибуты конкретного компилятора, например исторически встречавшиеся:

__attribute__((...))

или:

__declspec(...)

В современном переносимом C++ предпочтительно сначала смотреть, существует ли стандартный атрибут для нужной задачи.

10. Хороший стиль функций

Хорошая функция обычно:

1. Делает одну понятную вещь

Плохо:

processStudentAndSaveFileAndPrintReport();

У функции слишком много обязанностей.

Лучше разделить.

2. Имеет понятное имя

Плохо:

void f(int x);

Лучше:

bool openFile(char* nameFile);

Имя должно объяснять назначение.

3. Имеет небольшой и понятный интерфейс

Например:

double calculateArea(double radius);

понятно:

  • что принимает;
  • что возвращает;
  • что делает.

4. Не использует ненужные глобальные данные

На этом этапе достаточно правила:

Чем меньше скрытых зависимостей у функции, тем легче ее понимать и тестировать.
